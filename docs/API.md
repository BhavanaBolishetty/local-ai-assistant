# API Reference

Base URL for all examples: `http://localhost:8000` (the default when
running via `uv run uvicorn src.api.main:app --port 8000` or Docker
Compose). Interactive docs are also auto-generated by FastAPI at
[`/docs`](http://localhost:8000/docs) (Swagger UI) and
[`/redoc`](http://localhost:8000/redoc) once the backend is running.

## Health

### `GET /health`

Liveness check.

```bash
curl http://localhost:8000/health
```

```json
{"status": "ok"}
```

## Chat

### `POST /chat`

Send a full conversation, get back one complete reply. The client
resends the full message history each turn; `conversation_id` ties the
turn to a persisted row (a new one is generated server-side if omitted).
If the model calls any tools mid-turn (calculator, `get_current_datetime`,
`calculate_date_duration`, `search_documents`), each resolved call is
returned in `steps`.

```bash
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{
        "messages": [{"role": "user", "content": "What is 47 times 89?"}],
        "model": null,
        "conversation_id": null
      }'
```

```json
{
  "reply": "47 times 89 equals 4183.",
  "model": "qwen2.5:3b-instruct",
  "latency_ms": 2087.09,
  "conversation_id": "b6b1...",
  "steps": [
    {"tool_name": "calculator", "arguments": {"expression": "47 * 89"}, "result": "4183"}
  ]
}
```

### `POST /chat/stream`

Same request body as `/chat`, but streams the reply as it's generated.
`conversation_id` comes back in an `X-Conversation-Id` response header
(the body is just the event stream). The body is **NDJSON** — one JSON
object per line, either:

- `{"type": "content", "text": "..."}` — a real streamed token chunk, or
- `{"type": "step", "tool_name": "...", "arguments": {...}, "result": "..."}` —
  emitted once per resolved tool call, *before* the final answer streams in.

```bash
curl -N -X POST http://localhost:8000/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "What is 47 times 89?"}]}'
```

```
{"type": "step", "tool_name": "calculator", "arguments": {"expression": "47 * 89"}, "result": "4183"}
{"type": "content", "text": "The"}
{"type": "content", "text": " result"}
{"type": "content", "text": " is"}
{"type": "content", "text": " 4183."}
```

True token-by-token streaming is preserved for ordinary questions that
need no tool at all — the tool-detection step doesn't add latency to
the common case.

## Conversations

### `GET /conversations`

List past conversations (id, title, created_at — not their messages).

```bash
curl http://localhost:8000/conversations
```

```json
[
  {"id": "b6b1...", "title": "What is 47 times 89?", "created_at": "2026-07-30T02:57:49"}
]
```

### `GET /conversations/{id}`

Load one conversation with its full message history. `404` if the id
doesn't exist.

```bash
curl http://localhost:8000/conversations/b6b1...
```

### `DELETE /conversations/{id}`

Delete a conversation. `204 No Content` on success.

```bash
curl -X DELETE http://localhost:8000/conversations/b6b1...
```

## Documents (RAG)

Uploaded documents are chunked, embedded (`nomic-embed-text`), and
automatically consulted on every chat turn — no separate "RAG mode" to
enable. Supported types: `.txt`, `.md`, `.pdf`, `.docx`.

### `POST /documents`

```bash
curl -X POST http://localhost:8000/documents \
  -F "file=@notes.pdf;type=application/pdf"
```

```json
{
  "id": "28ac93b6-...",
  "filename": "notes.pdf",
  "uploaded_at": "2026-07-30T22:56:18",
  "chunk_count": 6
}
```

Re-uploading a file with the same name replaces the existing entry
rather than creating a duplicate. Unsupported extensions return `400`.

### `GET /documents`

```bash
curl http://localhost:8000/documents
```

### `DELETE /documents/{id}`

```bash
curl -X DELETE http://localhost:8000/documents/28ac93b6-...
```

## Voice

### `POST /voice/transcribe`

Speech-to-text via Faster-Whisper. Accepts any audio file format
`ffmpeg`/`av` can decode (the browser records WAV via `st.chat_input`'s
built-in recorder).

```bash
curl -X POST http://localhost:8000/voice/transcribe \
  -F "file=@recording.wav;type=audio/wav"
```

```json
{"text": "What is the weather like today"}
```

### `POST /voice/speak`

Text-to-speech via Piper. Returns raw WAV bytes directly (not JSON).

```bash
curl -X POST http://localhost:8000/voice/speak \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello there"}' \
  --output reply.wav
```

## Vision

### `POST /vision/ask`

Ask a question about an attached image (`moondream`). One-shot: the
image is used only for this turn and is never persisted or resent —
follow-up questions in the same conversation go through the normal
`/chat` pipeline above. Streams the answer as plain text;
`conversation_id` comes back in an `X-Conversation-Id` header (generated
if omitted).

```bash
curl -N -X POST http://localhost:8000/vision/ask \
  -F "image=@photo.png;type=image/png" \
  -F "text=What do you see in this image?" \
  -F "conversation_id="
```
